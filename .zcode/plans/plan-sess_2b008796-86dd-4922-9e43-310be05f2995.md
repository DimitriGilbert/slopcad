## Overview

Three features turning slopcad into an agent-operable CAD tool:

1. **`@slopcad/cad-jsx` + `.tsx` as a first-class exchange format** — the missing declarative React binding from PRD §23/§32: CAD models authored as `.tsx` React files, compiled deterministically to the existing `CadCommand` vocabulary, **importable and exportable directly in the workbench** (import dialog accepts `.tsx`, export dialog emits `.tsx`), plus a compile CLI and native-format emission. JSX is sugar over `applyCommand` — the "no second parametric representation" law (`packages/cad-react/src/model.ts`) is respected.
2. **WebMCP** — the W3C draft protocol (spec: https://webmachinelearning.github.io/webmcp/; Chrome: https://developer.chrome.com/docs/ai/webmcp, imperative API https://developer.chrome.com/docs/ai/webmcp/imperative-api): the React app registers typed tools on `document.modelContext` for browser agents. Handlers drive the same domain state as the UI (CadProvider store, tRPC client, command-surface verbs). No server endpoint, no API keys — the user's session is the auth. Safe no-op where the API is absent; an internal registry is the testable source of truth.
3. **Tutorial studio** — teaching videos ("where to find what, where to click, what to change and why"), built on the session-harness driving code: gliding visible cursor + click ripples, deliberate pacing, per-chapter educational narration, WebVTT caption tracks + chapter index + ffmpeg cutting. Caption cues are the single narration source, so TTS audio can be muxed in later without re-recording.

## Decisions (documented)

- **Skill location: `skills/` directory at the project root.** The skill is a committed repo artifact at `skills/slopcad-cad-jsx/SKILL.md` — it travels with the repository and distributes off this machine. AGENTS.md gets a load rule pointing every agent working in this repo at that exact path (mirroring the `formedible` line). Nothing goes into `.zcode/`.
- **`.tsx` import/export are workbench features, not just CLI**: import via a server route (`/api/io/import-tsx`, pattern of `apps/web/src/routes/api/io/import-3mf.ts`: session-gated 401, body cap, then esbuild transpile → sandboxed `node:vm` evaluate exposing only react + cad-jsx elements → `compileModel` → native string → existing import apply); export via a pure document→TSX generator. Byte-stable round-trip is a hard test: `model.tsx → native → document → generated.tsx → native` identical.
- **WebMCP = the browser-native spec**, imperative API only. Declarative `<form toolname=…>` annotations deferred (that half of the spec is TODO in the draft). A server-side MCP endpoint is explicitly out of scope.
- **Auth**: none added. WebMCP handlers run in the logged-in page; mutations ride existing session-scoped paths.
- **Tutorials**: master recording + chapter cuts (ffmpeg), silent video + captions, TTS extension point documented but not built. Videos are generated artifacts (gitignored under `docs/tutorials/media/`); transcripts, chapter JSON, VTT, and the index are committed.
- **Dependencies**: react/zod from the catalog; `esbuild` added as a direct dep only where the TSX import route needs it (already in the lockfile transitively via vite); `document.modelContext` gets a local minimal TS interface matching the spec IDL; ffmpeg stays a system prerequisite for cutting only.
- Command-surface checklist changes only as data (the recorded "couriers extend as data" pattern) if the new import/export formats require claiming; `pnpm audit:command-surface` must stay green.

## Phase 4 — `.tsx` import/export in the workbench
**Type**: Sequential
- **Import**: `apps/web/src/routes/api/io/import-tsx.ts` + logic module (pattern: `import-3mf-endpoint.ts`): session-gated 401, body cap, esbuild transpile TSX→JS, evaluate in `node:vm` sandbox exposing ONLY react createElement + cad-jsx element runtime (no fs/network/process), run `compileModel`, return native string; the client applies it through the existing import path. Import dialog (Formedible) accepts `.tsx` files.
- **Export**: `generateTsx(document)` pure generator in cad-jsx (feature DAG → JSX tree; shared/reused features become top-level elements with `id`s consumed by reference; non-representable records — e.g. configurations, appearances beyond vocabulary — produce an honest, structured decline note in the emitted file header, never silent loss). Export dialog gains TSX format.
- **Round-trip proof (hard gate)**: `model.tsx → native N1 → document → generated.tsx → native N2` with `N1 === N2`, as unit tests over a representative model set.

**Validation**: endpoint tests (auth 401, cap 413, sandbox refusal of forbidden imports); generator tests incl. shared-input reference case; session harness green; `pnpm audit:command-surface` green.
