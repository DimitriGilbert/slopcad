# The tutorial studio

The tutorial is the recorded, narrated walk a new user watches: 30 chapters
that tour the whole app at teaching pace — the home page, the sketch
workspace, every feature family, the assembly workbenches, analysis,
drawings, exchange, and the projects loop. It lives in
`apps/web/e2e-tutorial/` (the harness) and `docs/tutorials/` (the
artifacts). The harness is the teaching twin of the session e2e
([testing](testing.md)): the same production boot and determinism setup,
but every pointer move glides, every click ripples, and every narration
cue is held long enough to read.

## The artifacts

| Path                                | Committed | What it is                                                                                                                                                                 |
| ----------------------------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `docs/tutorials/chapters.json`      | yes       | The cut list and narration source: every chapter's window and every cue's stable id, text, and master-video timestamps. Written by `e2e-tutorial/tutorial-reporter.ts`.    |
| `docs/tutorials/index.md`           | yes       | The searchable index, GENERATED by `tutorial:cut` — chapter windows, clip paths, full timestamped transcripts, and the command-surface coverage map. Never edited by hand. |
| `docs/tutorials/media/master.webm`  | no        | The whole-tutorial recording (1280×720, one browser context for all 30 chapters). Gitignored, regenerated per recording.                                                   |
| `docs/tutorials/media/master.vtt`   | no        | The caption track: all 301 cues on the master timeline.                                                                                                                    |
| `docs/tutorials/media/chapters.vtt` | no        | The chapter track: one marker per chapter at its recorded start.                                                                                                           |
| `docs/tutorials/media/clips/`       | no        | Per-chapter cuts (`<chapter-id>.webm`) and their re-timed captions (`<chapter-id>.vtt`), written by `tutorial:cut`.                                                        |

The split is deliberate: everything a human curates or a future tool reads
as data is committed; everything derived from a specific recording is
regenerated. `chapters.json` and `index.md` move together — timestamps
change on every recording, so after each `tutorial:record`, re-run
`tutorial:cut` and commit the regenerated pair.

## Watching

Play `docs/tutorials/media/master.webm` with `master.vtt` as a subtitle
track (any player that loads WebVTT, or a `<video>` element with a
`<track>`); `chapters.vtt` carries the chapter markers in the same format.
For a single chapter, play its clip under `media/clips/` — each clip's
`.vtt` is the same cues re-timed onto the clip's own zero — and use the
chapter's master window in `index.md` to find it in the full recording.

## Recording and cutting

```sh
pnpm tutorial:record   # the whole walk: ~14 min at teaching pace
pnpm tutorial:cut      # clips, per-clip captions, index.md — needs ffmpeg
```

Both root aliases delegate to `apps/web` (`pnpm --filter web …`).
`tutorial:record` boots the real production stack (committed migrations →
build → nitro server) and walks all 30 chapters serially in ONE browser
context, so the recording is one master video; the final gate test
validates the narration ledger and the reporter writes `docs/tutorials/`.
`tutorial:cut` (`apps/web/scripts/tutorial-cut.mjs`) then cuts per-chapter
clips with ffmpeg — decode-accurate seek plus a libvpx-vp9 re-encode,
because stream copy on these sparse-keyframe Playwright recordings snaps
every cut to a keyframe — verifies each clip's duration against its
chapter window, regenerates the per-clip captions from `chapters.json`,
and rebuilds `index.md`. The clips folder is wiped on every run, so stale
clips never survive. Every missing prerequisite fails loudly with the fix
named: no ffmpeg on PATH, no cut list, no master recording.

## The debug loop

Standing-server fast path — the config skips its own boot when
`TUTORIAL_E2E_BASE_URL` is set:

```sh
TUTORIAL_E2E_BASE_URL=http://localhost:3214 \
pnpm --filter web exec playwright test -c playwright.tutorial.config.ts \
  --grep "chapter: sweep-feature"
```

Two env knobs pace the teaching (both in `e2e-tutorial/driver.ts`, both
env-overridable): `TUTORIAL_DWELL_MS` (default 600) is the beat between
teaching actions, and `TUTORIAL_CUE_HOLD_MS` (default 1 200) is the
minimum on-screen life of one narration cue. Drive both toward 0 for a
fast structural pass, leave them at defaults for anything that will be
watched or cut — the timestamps in `chapters.json` are real wall-clock
stamps, so a sped-up run produces a sped-up video.

## The narration seam (TTS extension point)

`chapters.json` is the single narration source, and its cue ids are
stable: `chapterId/stepId`, where the step ids come from the chapter
definitions in `apps/web/e2e-tutorial/chapters/*.ts` and never change
between recordings — only their timestamps do. A future TTS pass
synthesizes one audio segment per cue id, aligns it to the cue's recorded
window (or its per-clip window — `tutorial:cut` already implements that
re-timing for the captions), and muxes the result without re-recording a
single frame. The seam is deliberately data-only: narration is text bound
to recorded time, never burned into the pixels, so voices can change
without the video changing.

## The coverage map

`index.md` closes with the tutorial-level analogue of the session coverage
gate: every `apps/web/e2e-workbench/command-surface.checklist.json` entry
id mapped to the chapter that teaches it — or listed under an explicit
"not taught" heading with the reason. The map is curated in
`apps/web/scripts/tutorial-cut.mjs` (`TAUGHT` / `NOT_TAUGHT`) and
validated mechanically on every `tutorial:cut` run: an entry that loses
its chapter, a cue id that no longer exists, or a checklist entry the map
does not mention fails the cut instead of silently shrinking the index.

## Harness anatomy

A chapter is a definition plus a script (`ChapterModule` in
`e2e-tutorial/narration.ts`): the definition holds the identity and the
ordered cue list; `run(page, driver)` performs the walk through the
driver's human-paced verbs (`humanClick`, `clickCanvasPoint`,
`clickCommandRow`, `pointAtReadout`, …), and every `driver.step(id)` opens
one cue's beat. Chapters play as serial tests over one worker-scoped page
fixture, so one context produces one master video; a visible cursor
overlay (`installCursorOverlay`) rides every page so the viewer always
sees where to look. The gate test binds every cue to its recorded step and
throws on any defect — a chapter that never ran, a step without a cue,
timestamps out of order — before the reporter emits the artifacts.
